# 潮汕文盲老人家识字系统 —— 技术架构与核心逻辑文档

## 一、 项目背景与设计哲学

### 1.1 目标受众特征
本项目专为**潮汕地区高龄文盲、半文盲老人**（70~85岁+）量身定制。该群体具有极度鲜明的生理与认知特征：
- **认知层面**：未受过正规汉字初等教育，无拼音（Pinyin）认知能力，但对**潮汕方言（揭阳音/潮阳音）**拥有数十年的母语熟练度，对潮汕日常生活物事（工夫茶、厨房烹饪、农耕家事）具有深刻的肌肉记忆与生活经验；
- **生理层面**：指尖触控面积大、存在生理性手部轻度震颤、眼部退行性老花（对低对比度或复杂细节辨识困难）、短期记忆力弱；
- **心理层面**：面对现代智能终端容易产生畏难或挫败情绪，极度依赖即时、温和的正向情绪激励，排斥刺耳的报警报错提示。

### 1.2 核心教学哲学：具身认知（Embodied Cognition）
传统识字应用采用“看字记音”或“拼音拼读”的抽象符号教学，对文盲老人完全失效。本项目严格遵循**具身认知**理论：
1. **见物知音（生活唤醒）**：先看到老茶盘上熟悉的紫砂“冲罐”、砂铫或厨房的“黑铁鼎”，点击即听见亲切正宗的潮汕方言读音；
2. **由物入字（骨架映射）**：由生活物件引出对应的汉字，通过慢速、优雅的书法笔画动画展现该字的起承转合；
3. **触觉固化（手写磁吸）**：在无压力的画布上以手指临摹描红，系统自动容错、纠偏并磁吸成型，奏响五音和弦，给老人满满的成就感；
4. **融会贯通（国语引申）**：在建立形义认知后，适度引导听辨慢速标准普通话，构建从母语方言向规范汉字的桥梁。

### 1.3 硬件基准与性能红线：iPad mini 2 (iOS 12)
系统以老旧低配平板 **iPad mini 2（2013年发布，Apple A7 处理器，1GB LPDDR3 内存，最高系统版本 iOS 12.5.7）** 为最低基准基线，同时完美自适应现代 Android 平板、现代 iPad 以及 PC 浏览器调试：
- **内存红线**：全应用运行时内存严格压制在 **80MB 以内**（3D 实景漫游运行峰值严格控制在 60~65MB 以内，练字状态下完全挂起 3D 渲染，字盘运行内存 < 45MB），坚决避免触发 iOS 12 WebKit 的内存溢出杀死（Jetsam Out-Of-Memory Crash）；
- **首屏与冷启动**：整包预构建与极简按需加载，在低速 Wi-Fi 下冷启动时间 < 500ms；
- **无笨重 UI 框架**：不引入 Element、Vant、AntDesign 等庞大框架，全部采用纯原生精简组件与自适应 CSS；
- **适老与低配兼容的 3D 图形架构**：三维空间采用精简低模（Low-Poly）纯程序化几何建模，零动态阴影计算、零高分辨率外部贴图加载、共享基础材质，结合识字态自动挂起（Auto Pause），在老旧设备上稳定维持 60 FPS 且不发烫。

## 三、 核心模块与业务逻辑深度拆解

### 3.1 适老化高容错手写识别引擎 (`strokeMatcher.ts`)

这是全系统最具创新性与技术含量的模块。传统 OCR 或严格的手写匹配要求笔画严丝合缝，会导致手抖、指粗的老人频频受挫。本项目基于**几何拓扑降采样**与**多维动态加权评分**，打造了响应时间 `< 2ms` 的自研极速匹配算法。

#### 1. 屏幕坐标转虚拟空间映射 (`clientToSvg`)
无论老人家在何种尺寸的屏幕上书写，所有触摸点通过当前容器的 `getBoundingClientRect()` 动态投射至标准 `800 × 800` 的虚拟坐标系中：
$$x_{svg} = (x_{client} - \text{rect.left}) \times \frac{800}{\text{rect.width}}$$
$$y_{svg} = (y_{client} - \text{rect.top}) \times \frac{800}{\text{rect.height}}$$

#### 2. 等距弧长重采样归一化 (`resamplePoints`)
老人运笔往往时快时慢，或者中途停顿产生局部密集点簇。算法沿手写折线累积弧长，将其重采样为 **$N=16$ 个等弧长分布的特征几何点**：
- 计算用户手写折线全长 $L = \sum_{i=1}^{m-1} \text{dist}(P_i, P_{i+1})$；
- 步长 $\Delta s = \frac{L}{N - 1}$；
- 线性插值生成 $U = [u_0, u_1, \dots, u_{15}]$。
同理，标准字体的 SVG Path 也被预解析并重采样为 $T = [t_0, t_1, \dots, t_{15}]$。

#### 3. 运笔主方向余弦校验（防止逆向倒笔画）
文盲老人书写极易出现“从右向左画横”、“从下向上画竖”的错误倒笔习惯。
算法提取用户首尾主向量 $\vec{u} = u_{15} - u_0$ 与标准主向量 $\vec{t} = t_{15} - t_0$，计算向量余弦夹角：
$$\cos\theta = \frac{\vec{u} \cdot \vec{t}}{\|\vec{u}\| \|\vec{t}\|}$$
- **判定阈值**：当 $\cos\theta < 0.25$（即两向量夹角 $\theta > 75.5^\circ$ 时），无论轨迹多么重合，均果断判定为方向相反：
  ```ts
  if (cosTheta < 0.25) {
    return {
      isMatch: false,
      score: 20,
      reason: 'direction_reverse',
      message: '笔画方向反了，顺着箭头划'
    };
  }
  ```

#### 4. 四维加权适老评分模型
算法综合考量老人的起笔位置、收笔位置、方向平顺性以及中间形状相似度，各赋予 25% 权重：
1. **起点误差分**：$s_{start} = \max(0, 1 - \frac{d_{start}}{1.5 \times \text{tol}_{start}}) \times 25$ （起笔容差半径为 95px）
2. **终点误差分**：$s_{end} = \max(0, 1 - \frac{d_{end}}{1.5 \times \text{tol}_{end}}) \times 25$ （收笔容差半径为 110px）
3. **方向一致分**：$s_{dir} = \max(0, \frac{\cos\theta + 1}{2}) \times 25$
4. **整体形似分**：计算采样点平均欧氏距离 $\bar{d} = \frac{1}{16} \sum_{i=0}^{15} \|u_i - t_i\|$，得出 $s_{shape} = \max(0, 1 - \frac{\bar{d}}{120}) \times 25$

**通过条件（宽容及格线 58 分，相当于 55% 宽松度）**：
$$d_{start} \le 95 \land d_{end} \le 110 \land \bar{d} \le 85 \land \text{TotalScore} \ge 58$$
一旦及格，立即吸附对齐为规范笔画，触发金光涟漪与和弦提示；未及格则由系统指出温和的原因提示（“从起点起笔”、“划长一点”、“顺着箭头划”）。

### 3.2 声音调度与纯硬件合成引擎 (`audioService.ts`)

在低端设备上，频繁播放大量音频文件极易造成内存泄漏或 I/O 卡死。本项目采用**物理振荡器实时合成**与**录音文件即时中断机制**结合的方式。

#### 1. iOS 12 自动播放拦截解除机制 (`unlockAudio`)
iOS Safari 强制限制必须在用户首次手势交互事件中才能激活音频上下文。系统在全屏根节点监听 `@touchstart` 与 `@mousedown`：
```ts
const AudioContextClass = window.AudioContext || (window as any).webkitAudioContext;
this.ctx = new AudioContextClass();
// 创建 1 样本微型静音缓冲区并播放，强制唤醒硬件通道
const buffer = this.ctx.createBuffer(1, 1, 22050);
const source = this.ctx.createBufferSource();
source.buffer = buffer;
source.connect(this.ctx.destination);
source.start(0);
if (this.ctx.state === 'suspended') this.ctx.resume();
```

#### 2. 即时中断与防串音治理 (`stopAllAudio`)
当老人快速连续点击多个物件或切换字时，前一个声音若继续播放会导致杂音刺耳。`stopAllAudio` 实现了毫秒级硬中断：
- 暂停并重置 `HTMLAudioElement`，清除所有事件回调；
- 立即执行 `window.speechSynthesis.cancel()` 截断国语语音队列。

#### 3. 硬件级纯合成音效设计
无需下载网络资源，通过 Web Audio API 的 `OscillatorNode` 与 `GainNode` 实时运算声音曲线：
- **毛笔写字声 (`playStrokeSound`)**：正弦波由 580Hz 线性扫频衰减至 320Hz，模拟毛笔摩擦宣纸的沉稳沙沙声（时长 280ms）；
- **紫砂/瓷杯碰杯声 (`playCupClink`)**：1760Hz 高音骤降至 880Hz 指数衰减（时长 800ms），清脆悦耳；
- **倒水水滴声 (`playWaterDrip`)**：480~680Hz 频率在 90ms 内急促上升至 2.2 倍频，高度还原茶水注入杯中的水滴声；
- **通关五音和弦 (`playSuccessChime`)**：取中国传统雅乐五声音阶（**宫-商-角-徵-羽**），采用三角波依次间隔 100ms 奏响，营造温馨自然的工夫茶韵味：
  - 宫（C5: 523.25 Hz）
  - 商（D5: 587.33 Hz）
  - 角（E5: 659.25 Hz）
  - 徵（G5: 783.99 Hz）
  - 羽（A5: 880.00 Hz）

#### 4. 双轨语音设计
- **潮汕本土乡音**：加载 `/audio/*.mp3` 本地真实录音切片，包含 13 个代表性核心汉字；
- **国语慢速跟读**：调用 Web Speech API，特意设置 `rate = 0.85`（较普通话标准语速放慢 15%），保证老人家听得真切、跟得上。

### 3.3 汉字笔画矢量骨架体系与国标校准

#### 1. 字体视觉呈现选择历程
在前期迭代中，系统探索了两种截然不同的字形方案：
- **方案一（最终选用）：Hanzi Writer 权威书法中线（Medians）**：具备自然舒展的转折弧度与楷书骨架比例，既美观又符合老人家对汉字传统书写美感的潜意识认同；
- **方案二：温润幼圆体（极简直线）**：试图将所有折笔压平为机械水平线与垂直线，经过老人实际试用，发现过度几何化导致部分汉字（如“鼎”、“炒”）结构怪异失真，辨识度显著下降。
- **最终落地标准**：全量回归 **Hanzi Writer 权威书法中线轨迹**。同时对视觉容器进行彻底的“去杂质”净化：**完全删除底部多余的文字黑色阴影（text-shadow）与楷体垫底字，使用 42px 宽度的纯净暖金圆头线条（#FFD54F）进行渲染**，极大提升了视弱老人的辨识舒适度。

### 3.4 具身生活双实景构建与两梯次识字体系

全系统划分为两个鲜活的潮汕生活实景，并创新引入**“基础物事” (basic) 与“进阶拓展” (advanced) 两梯次渐进式识字架构**（全量共收录 27 个高频核心汉字）。老人家在实景中可通过顶部的实体药丸胶囊（`tier-switcher-bar`）自如切换梯次，进入字盘后顶部的 `word-picker-bar` 亦支持全局 13~14 字横向平滑点选与无缝切换。

#### 1. 场景一：“厝内工夫” (`teaTableScene.ts` & `TeaTableScene.vue`，共 13 字)
- **文化意象**：老厝客厅工夫茶桌，从泡茶基础器具延伸至潮汕工夫茶待客礼俗与感官体验。
- **第一梯次·基础物事（6字，核心器物）**：
  1. `tea`（**茶**，dê⁵ / 9画）—— 对应器物：朱泥小冲罐
  2. `water`（**水**，zui² / 4画）—— 对应器物：提梁竹编砂铫

### 3.6 三维潮汕老厝大院与空间导览架构 (`ChaozhouHouse3DScene.vue` & `3d/`)

为了让老人家获得置身家乡故土的真实空间沉浸感，系统突破了传统的平铺二维画面，创新构建了**“下山虎”传统潮汕老厝大院三维全景空间**。该模块将“厝内工夫”与“灶下炊事”两大生活场景熔铸于统一的物理院落中，支持全局 27 个生活核心字的立体探索与点击识字。

#### 1. 适老级受限三级运镜总监 (`cameraDirector.ts`)
文盲高龄老人极易在开放自由视角（如 FPS 第一人称、全向 OrbitControls）中产生眩晕或迷失方向。运镜总监针对老人定制了**“三级离散预设机位 + 限制性平滑过渡”**机制：
- **三级固定机位（Waypoints）**：
  - `overview`（**全院鸟瞰**）：位于院落南端斜上方，将青石天井、正厅茶席、侧翼灶房、水缸瓦檐尽收眼底，展示醒目的房间导航地标卡；
  - `tea_table`（**茶席特写**）：摄像机推轨平滑平移至正厅太师壁前，聚焦老茶盘、朱泥冲罐、若琛瓯三杯、橄榄茶配；
  - `kitchen`（**灶台特写**）：摄像机移步至侧房柴火灶台，大铁鼎、竹蒸笼、案板切刀、荔枝柴火一览无余；
- **余弦缓动插值**：摄像机位移与朝向插值采用 Smooth Cosine 缓动曲线，平稳无顿挫，单次镜头推拉时间设定为 1.2 秒；
- **防眩晕触控限位**：老人在单指拖曳查看时，水平偏航角（Yaw）被严格限制在 $\pm 20^\circ$，垂直俯仰角（Pitch）限制在 $\pm 10^\circ$，松手后柔和弹性阻尼回中，杜绝任何翻转倒立或出画失控。

#### 2. 程序化低模老厝与生活物事建模 (`houseGeometry.ts` & `itemMeshes.ts`)
为确保在 iOS 12 / A7 芯片上的极限流畅与零网络下载延迟，全部三维模型均采用**原生代码程序化构造（Procedural Low-Poly）**：
- **老厝建筑形制**：基于 `BoxGeometry`、`CylinderGeometry` 等基础几何体，手工拼合老厝院落的地面青石板、回廊立柱、雕花大梁、硬山顶黑瓦与微翘飞檐卷草、红灯笼以及灶房排烟烟囱；
- **27 件生活物事建模**：细致建模了冲罐（朱泥壶身与流嘴提钮）、砂铫、茶杯、石茶盘、西施壶、茶仓、公鸡海碗、双耳生铁大鼎、三层竹蒸笼、木柄菜刀与砧板切片、红木柴把、调味陶罐等；
- **隐形射线碰撞盒**：在物事周围自动绑定放大尺寸的 `invisible` BoxCollider，老人即使手指粗大轻微偏位，也能百分之百精准触发射线拾取（Raycasting）。

#### 3. 三维空间锚点向 2D 黄金字标投射系统 (`toScreenPosition` + HTML 覆盖层)
三维贴图在低分辨率屏幕或不同景深下容易模糊或产生摩尔纹，对视力退化的老人极其不友好。系统首创**“3D 空间锚点投影 + 2D 纯净黄金胶囊”**方案：
- **空间点投影运算**：物事的三维局部坐标转换至世界坐标后，利用相机矩阵进行屏幕归一化映射：
  $$\mathbf{p}_{ndc} = \mathbf{p}_{world} \cdot \mathbf{M}_{view} \cdot \mathbf{M}_{proj}$$
  $$X_{screen} = \frac{\mathbf{p}_{ndc}.x + 1}{2} \times W_{canvas}, \quad Y_{screen} = \frac{1 - \mathbf{p}_{ndc}.y}{2} \times H_{canvas}$$
- **2D 悬浮胶囊字标**：在 WebGL 画布上方覆盖绝对定位的 HTML 徽标（`item-badge-pill`）。胶囊包含正楷大汉字、发音图标，并配有柔和的金黄色呼吸光晕与景深缩放；点击不仅立即播报正宗方言读音，更无缝呼出毛笔识字盘。

#### 4. iOS 12 极限低显存与渲染挂起保护机制
- **零动态阴影计算**：关闭所有 `castShadow` / `receiveShadow`，光照统一采用一个适度环境光 `AmbientLight` 搭配斜向柔和平行光 `DirectionalLight`，绘制开销降低 80%；
- **共享基础材质**：全场景共享轻量级 `MeshLambertMaterial`，几何顶点总数控制在 4,000 以内，Draw Calls 控制在 30 左右；
- **识字态自动挂起（GPU 免载）**：当老人点击字标进入 `LiteracyFocusView` 临摹练字时，`App.vue` 向 3D 组件传递 `:paused="true"`，组件立即通过 `cancelAnimationFrame` **100% 挂起三维渲染循环**，将全部 CPU 与 GPU 算力释放给 2D 矢量描红与笔画匹配；老人练完返回院落时秒级恢复；
- **全量显存自愈销毁**：组件 `onBeforeUnmount` 深度递归遍历 Scene 树，逐一执行 `geometry.dispose()` 与 `material.dispose()`，彻底清除 WebGL 上下文，杜绝老旧设备长期运行内存泄漏。

## 五、 未来扩展指南

### 5.1 如何扩展一个全新的生活场景（如：“田头农耕”）
1. **定义场景数据**：在 `src/data/scenes/` 下新建 `farmScene.ts`，定义 `id: 'farm'`, `name: '田头劳作'`，声明所含汉字（如：牛、犁、田、稻、水）；
2. **在注册表中挂载**：在 `src/data/index.ts` 的 `SCENES` 中引入并注册 `farmSceneConfig`；
3. **编写实景渲染组件**：在 `src/components/scenes/` 下创建 `FarmScene.vue`，用矢量图元绘制水牛、耕犁与稻田交互热区，点击物件时触发 `emit('select-word', wordId)`；
4. **App.vue 关联**：在 `App.vue` 的 `SCENE_COMPONENTS` 字典中增加 `farm: FarmScene` 映射。系统即可全自动完成新实景与识字引擎的双向联动。

### 5.2 如何添加一个新汉字
1. 使用标准化 800×800 虚拟空间，提取该字的 Hanzi Writer 中线坐标点；
2. 在对应场景的 `words` 对象中新增该字节点，配置 `pinyin`、`teochewIPA`、音频相对路径及各笔画数组；
3. 将方言发音切片放置于 `public/audio/<filename>.mp3` 即可，零额外编码。
